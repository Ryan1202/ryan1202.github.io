Run queue

Choosing the next kernel thread

Each CPU has scheduler state for its current thread, idle thread and ready queue. The queue stores its links inside the thread objects. Runnable threads join at the tail, and the next selection removes the head. A running thread that yields can return to the tail, giving other ready threads a turn.

When a running thread blocks and the queue is empty, the scheduler switches to the idle thread. The idle loop waits for an interrupt and gives the kernel a place to resume work when an event arrives.

Switch

Saving context and finishing a switch

The x86_64 switch code saves the callee-saved registers on the outgoing kernel stack and records its stack pointer. It loads the incoming thread’s stack pointer, restores the saved registers and returns through that stack. A new kernel thread starts with a prepared frame that returns to its entry trampoline.

The incoming thread completes the handoff by clearing the outgoing thread’s on_cpu marker. When the outgoing thread has exited, this path also removes the thread manager’s reference. The stack remains owned by the thread object until its references are released.

Wakeup

Waiting without losing a wakeup

A waiter checks its condition under the condition lock. If the condition is false, it joins the wait queue in the Blocking state. An early wakeup can return it to Running so it rechecks the condition without switching stacks. Otherwise it commits to Blocked and switches away.

A wakeup after that commit marks the thread Waking. If on_cpu is still set, switch cleanup can put it back on the ready queue. The waking path can enqueue it directly once the thread is off the CPU. Both paths use the same Waking-to-Ready transition under the queue lock, so only one can enqueue it.

Preemption

Deferring preemption during CPU-local work

PreemptGuard increments a per-CPU counter. Nested guards leave preemption disabled until the outermost guard is released. Scheduler lookups borrow a guard so code can keep using the current CPU’s scheduler state across a sequence of operations.

The context-switch path deliberately carries that preemption state across stacks and restores the guard on the receiving side. It saves and disables local interrupts separately for the short handoff of CPU ownership between the two threads.

Interfaces

Completions and C thread handles

Completion builds a counted event on top of a wait queue. Completing work records one event and wakes at most one waiter. A waiter consumes one event, so a completion published before a waiter arrives can still satisfy that wait.

C callers create a registered thread with thread_create and make it runnable with thread_run. The creation pointer is borrowed. Code that needs to retain it across execution takes an owning reference with thread_get before starting the thread and releases it with thread_put.
