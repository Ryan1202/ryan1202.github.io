Development history

Horizon

Horizon began as a 32-bit kernel in 2021. Its history runs from early experiments with booting and loading programs to a higher-half x86_64 kernel with core subsystems written in C and Rust.

View source
2021–2022

From booting to running programs

The first boot code needed a predictable kernel image. The July 2021 linker script selected ELF32 for i386, set the entry point to _start, and placed the image at 1 MiB. It also exposed the boundaries of the initialization routines so startup code could find them.

By July 2022, the next problem was loading a program from disk and giving it a way to call the kernel. The tree gained an ELF loader, changes to paging and process setup, and a test application built separately from the kernel. The system-call code gave that application an interface back into the kernel.

2023–2024

Real I/O and a new boot path

FAT32 access exposed two concrete problems: repeated reads of the allocation table and incorrect reads of large files. The January 2023 changes buffered the FAT table and fixed the large-file path.

In November 2024, Horizon moved from floppy boot to a hard-disk image booted by GRUB. Multiboot2 defined the handoff and gave the kernel a standard format for reading boot information such as the memory map.

FAT table buffering Large-file fix GRUB and Multiboot2
2025

Storage layers and the first Rust build

A storage request may cross partition, filesystem and device boundaries. The FAT32 rework introduced partition discovery, mountable objects and a block cache. Follow-up changes gave callers common create and delete operations and let the storage layer split requests to fit the device path.

Rust entered the build in October. The configurator learned to link a Rust static library into the existing C kernel, and an experimental kernel-side test exercised that route. The same build could then accommodate subsystem work in both languages.

Mar–Jun 2026

Rebuilding memory for x86_64

Small objects, contiguous physical frames and contiguous virtual ranges have different allocation requirements. The March rewrite split those jobs across object caches, a buddy allocator and virtual mappings, with Rust interfaces and a C ABI. The buddy allocator can merge matching free blocks to make larger contiguous allocations possible again.

The April move to x86_64 changed address widths and the paging hierarchy. Horizon added a path into long mode, revised the higher-half layout and corrected type and layout assumptions carried over from 32-bit code. Follow-up page-table work added locking, iteration and automatic reclamation of page-table pages.

Jul–Aug 2026

Thread lifetimes and CPU-local state

A thread can be woken while it is still switching away. Putting it back on the run queue too soon can make it runnable before the previous switch has finished. The wait-queue design records this intermediate state and lets switch cleanup complete the wakeup when the thread is still on a CPU.

The thread rewrite also moved scheduling and synchronization into Rust with interfaces for C callers. Static and dynamic per-CPU storage followed, giving kernel code separate instances for state that belongs to each processor.

Thread and synchronization rewrite Wait-queue design Schedule Dynamic per-CPU storage
Aug–Sep 2026

Discovering and routing interrupts

Interrupt routing depends on firmware-provided details. Horizon began reading ACPI tables to discover Local APIC and I/O APIC information and apply platform-specific ISA interrupt overrides. A separate AML effort built a namespace from the DSDT and added basic method execution.

The IRQ core separated logical interrupt numbers from the CPU vectors used to deliver them. Affinity then gave the routing code a set of eligible CPUs for a given IRQ, laying groundwork for steering interrupts on multicore systems.

ACPI discovery I/O APIC and ISA overrides AML method execution IRQ affinity
Nov 2026

A common interface for timer interrupts

The PIT and Local APIC timer have different programming interfaces. The clock-event layer gave periodic ticks a shared interface, with the PIT as the first provider. The Local APIC timer then gained calibration so the kernel could translate a requested period into a timer count and use it as another periodic source.
