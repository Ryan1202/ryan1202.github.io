Horizon / Development history

Horizon

Horizon began as a 32-bit kernel in January 2020 and was first uploaded to GitHub in July 2021. It grew from a basic boot and console into a higher-half x86_64 kernel with core subsystems written in C and Rust.

View source
Aug 2016 - Jan 2020

Learning from a working system

In August 2016, I bought 30日でできる！ OS自作入門, a guide to building your own operating system in 30 days. I taught myself by experimenting with the system from the book until January 2020, when I decided to write my own from scratch.

Jan–Dec 2020

The first 32-bit kernel

Development began in January 2020. From January through April, Horizon gained its boot path, PIC and PIT drivers, and basic print output.

Work from May through December filled out the original kernel. By the end of the year, the hard disk driver was the only part still pending.

Jul 2021

Horizon arrives on GitHub

Horizon was first uploaded to GitHub in July 2021, when its Git history begins. The early commits show an ELF32 linker script that placed the kernel image at 1 MiB and set the entry point to _start. The same month added a framework for bringing drivers into the kernel.

Initial source upload Kernel linker script First driver framework
Aug 2021

A virtual filesystem

The first virtual filesystem gave the kernel a tree of named files and directories. The FAT32 work and the VFS changes established separate interfaces for on-disk data and path-based operations.

Virtual filesystem
Sep 2021

User threads and system calls

Horizon added user-thread support and adjusted x86 paging, descriptors and context switching to start them. A system-call entry path and a small user library then gave code running in user mode a way to ask the kernel for services.

User threads System calls
Jul 2022

Programs loaded from disk

The kernel gained an ELF loader and a test application built separately from the kernel. The loader and process setup made a disk image a source of executable programs. A file operations API followed later in the month.

ELF loader and test app File operations API
Aug 2022

Sound Blaster support

Horizon added a Sound Blaster 16 driver. The same change fixed problems in the PIT timer, interrupt handling and the filesystem.

Sound Blaster 16 driver
Sep–Oct 2022

Finding USB hardware

September added 8-, 16- and 32-bit PCI configuration access and let drivers search by class, subclass and programming interface.

October introduced a UHCI host-controller driver. Driver initialization gained a way to report when the expected hardware was absent.

PCI configuration access UHCI host controller
Nov–Dec 2022

Automated builds and local tools

November added a GitHub Actions job that ran the build for pushes and pull requests on the main development branch.

December added a top-level make target for the tools directory and configured the editor to use the repository’s formatting rules.

Initial build workflow Tools target and formatting
Jan 2023

Faster and more reliable FAT32 reads

File reads were repeatedly accessing the FAT32 allocation table. Horizon added a buffer for the table and fixed a separate path that mishandled large files.

FAT table buffering Large-file fix
Jan–Apr 2023

Building the first network stack

January added an RTL8139 driver and the first Ethernet and ARP support, with a network-device manager connecting the driver to the protocol code. February added transmission of IPv4 and UDP packets.

March added IPv4 and UDP receive paths and basic DHCP. Follow-up work fixed repeated receive errors in the RTL8139 driver and corrected handling of DHCP acknowledgments.

April added active TCP connection setup and teardown, along with another fix to the RTL8139 receive path.

Ethernet and ARP IPv4 and UDP send Receive path and DHCP RTL8139 and DHCP fixes TCP connection lifecycle
Feb 2024

Revisiting TCP and RTL8139

The network stack gained further TCP functionality and fixes in both the protocol code and the RTL8139 driver. The same update made console scrolling faster.

TCP, RTL8139 and console updates
Aug & Oct 2024

Keyboard and USB initialization

August updated the i8042 keyboard-controller driver and fixed a bug in the kernel’s string-length routine.

October fixed another i8042 issue and extended UHCI so the kernel could initialize USB devices on the bus.

i8042 and string fix i8042 follow-up USB device initialization
Nov 2024

Booting from GRUB

Horizon moved from floppy boot to a hard-disk image booted by GRUB. Multiboot2 defined the handoff and gave the kernel a standard format for reading boot information such as the memory map.

GRUB and Multiboot2 Boot
Dec 2024

A framework for buses and devices

The driver rework introduced interfaces for interrupt controllers, timers and displays. Bus drivers and dependency tracking gave initialization a way to wait for the hardware and drivers it needed.

Device interfaces Bus drivers and dependencies Wait for driver initialization
Jan–Mar 2025

From disk requests to filesystem objects

January built a new IDE driver and storage manager. DMA support let the controller transfer data directly to or from memory, and request merging let the storage layer combine reads and writes.

February added a common transfer interface and MBR partition objects that callers could read and write through. The object system gained path lookup and reference counting as it took on more of the storage interface.

March connected FAT32 to mountable objects and a block cache. Common create and delete operations gave callers a single interface for files and directories, while request splitting let the storage layer break up transfers for the device.

IDE DMA Request merging Partition I/O FAT32 and block cache Common file operations Request splitting
Apr 2025

Emulating real-mode BIOS calls

An x86 interpreter began emulating part of the 16-bit real-mode instruction set for BIOS interrupt calls. The follow-up work added string and port I/O instructions, along with more control-flow and stack operations.

BIOS interrupt emulation Port I/O instructions
May 2025

Driver readiness and lock diagnostics

A bus driver could finish initialization without updating its state. Horizon fixed that transition and revised how dependent drivers waited for it. Debug builds gained the option to record which thread held a spinlock.

Driver readiness fix Spinlock diagnostics
Aug 2025

Deferred interrupts and preemption

The kernel added soft interrupts for deferred work, a way to disable preemption around critical regions, and timer callbacks. Driver dependency handling adopted the preemption control.

Soft interrupts Preemption control Timer callbacks
Aug–Sep 2025

Reworking the network stack

August reworked RTL8139, the network-device manager and the Ethernet, ARP, IPv4, UDP and DHCP layers. Neighbor discovery and address-conflict handling helped the stack track peers and detect duplicate addresses.

September added ICMP echo replies and TCP listening. TCP also gained maximum segment size handling and round-trip timing to calculate retransmission timeouts.

Network stack rewrite Neighbor discovery Address conflict handling ICMP echo replies TCP listening TCP retransmission timing
Sep–Oct 2025

USB and legacy input

September adapted UHCI to the new driver framework and moved enumeration to a dedicated thread. Interrupt transfers and USB request blocks supported basic HID keyboard and mouse reports.

October aligned input event IDs with USB HID usages and reworked PS/2 initialization so it could run after USB legacy support was disabled.

UHCI driver integration Threaded USB enumeration Basic HID input PS/2 driver rewrite
Oct 2025

Bringing Rust into the build

The build system and its configurator were rewritten in October. The configurator then gained support for linking a Rust static library into the C kernel, with an experimental Rust test in the kernel to exercise the new build path.

Build system rewrite Rust static linking
Oct 2025–Mar 2026

Redesigning page tables and memory allocation

From October to December 2025, Horizon gained a new page-table management design and a working first version of the SLUB allocator.

From December 2025 to March 2026, the memory interfaces were redesigned into the form Horizon uses today. The March implementation separated small-object allocation, contiguous physical frames and contiguous virtual ranges across SLUB object caches, a buddy allocator and virtual mappings, with Rust interfaces and a C ABI.

March memory rewrite Memory
Jan 2026

Merging the driver framework rework

The driver-framework branch merged in January. Its bus and device model, storage and USB work, and build tooling became part of the main development history.

Driver framework merge
Apr 2026

Moving to x86_64

The move to x86_64 introduced a path into long mode and revised the higher-half layout. The port corrected type and layout assumptions inherited from 32-bit code. Later in April, page-table locking and iteration were added alongside automatic reclamation of unused page-table pages.

x86_64 port Page-table locking and reclamation Boot
Jun 2026

A DMA layer for device buffers

Devices impose their own address and alignment limits on buffers. The DMA rewrite separated buffer allocation, mapping and synchronization. It introduced APIs for coherent buffers, pools and streaming transfers, and adapted the IDE and UHCI drivers. The same update fixed a leak in the buddy allocator.

DMA subsystem rewrite DMA ownership and lifecycle notes
Jul–Aug 2026

Thread lifetimes and per-CPU state

July moved scheduling and synchronization into Rust with interfaces for C callers. The wait-queue design tracks wakeups that arrive while a thread is switching away, so the switch can finish before the thread returns to the run queue.

August introduced static and dynamic per-CPU storage. Kernel code could give each processor its own instance of data that belongs to that CPU.

Thread and synchronization rewrite Wait-queue design Static per-CPU storage Dynamic per-CPU storage Schedule
Aug–Sep 2026

Reading ACPI and running AML

August added ACPI table discovery to locate the interrupt controllers and apply ISA interrupt overrides. The DSDT parser built an AML namespace and started executing methods.

September added AML operation regions backed by system memory or I/O ports. The interpreter also gained more control-flow instructions and mutex operations.

ACPI discovery I/O APIC and ISA overrides AML method execution AML operation regions AML mutex support
Sep 2026

IRQ routing and CPU affinity

The kernel acquired Rust xAPIC and I/O APIC drivers and connected the new IRQ core to the hardware interrupt path. The core separated logical IRQ numbers from the CPU vectors that deliver them. Affinity added a way to specify the CPUs eligible to receive an IRQ.

Hardware interrupt dispatch IRQ core rewrite IRQ affinity IRQ
Oct 2026

Updating the x86_64 build workflow

The linker script now explicitly selects the x86_64 output architecture. The GitHub Actions workflow moved its build artifact uploads to version 4 of the upload action.

x86_64 linker target Artifact upload workflow
Nov 2026

A common interface for timer interrupts

The PIT and Local APIC timer have different programming interfaces. The clock-event layer gave periodic ticks a shared interface, with the PIT as the first provider. The Local APIC timer then gained calibration so it could translate a period into a counter value and provide periodic events.

PIT clock events Local APIC timer calibration
