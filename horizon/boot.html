How Horizon starts from GRUB, enters x86_64 long mode and reaches the higher-half kernel.

Handoff

What GRUB passes to the kernel

The 2024 move from floppy boot to GRUB introduced the Multiboot2 handoff. GRUB finds the header in the kernel image and enters _start in 32-bit protected mode. It passes a magic value in EAX and the physical address of its information block in EBX.

Horizon saves both values before changing CPU modes. The loader validates the magic value and reads the tagged information block through a temporary mapping. It copies the memory map, framebuffer information and available ACPI root pointer into locations later initialization code can read.

CPU mode

Entering x86_64 long mode

The assembly entry builds a temporary page-table hierarchy with an identity mapping for the first 2 MiB. This lets instruction fetches continue at the same addresses when paging turns on. The entry enables PAE in CR4, loads the PML4 address into CR3, sets EFER.LME, and enables paging through CR0.

A far jump through the bootstrap GDT selects the 64-bit code segment. The loader then sets up a temporary stack and calls the C code that reads Multiboot2 tags.

Mappings

Jumping to the higher half

The linker script keeps the Multiboot2 and early initialization sections at low addresses. It gives the main kernel high virtual addresses while keeping its load addresses low. From kernel_early_start, page_early_setup builds the initial higher-half alias using 2 MiB pages.

The kernel jumps to its high virtual entry and switches to the higher-half stack address. Early memory initialization then removes the temporary low identity mapping. The higher-half alias keeps the stack and kernel image accessible during that handoff.

Early init

Turning the boot map into allocatable memory

The full allocator needs frame metadata and page tables before it can hand out pages. Early initialization uses a page-aligned cursor after the kernel image to allocate those structures. It records the cursor so the new allocator can skip the space already consumed.

The frame initializer walks the map copied from Multiboot2 and marks the ranges occupied by the kernel and early allocations. Once frame metadata is ready, the buddy allocator takes over the free ranges. Kernel startup then initializes the object caches, virtual mapping allocator, per-CPU storage and DMA bounce buffer pool.

Platform

Bringing up the first devices

Early platform setup installs the kernel’s segment and interrupt descriptors and reads CPU features. After memory initialization, the main entry initializes ACPI and the core device managers. Platform setup then reads the firmware’s x86 topology before configuring interrupt controllers and timers.

The platform starts the framebuffer console and enables CPU interrupts once the controller and entry paths are ready. At that point, periodic events can drive Local APIC timer calibration.
