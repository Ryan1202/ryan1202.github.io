Memory

How Horizon allocates physical frames, maps virtual pages and manages small objects and DMA buffers.

View source
Frames

Physical frames and allocation zones

The buddy allocator groups physically contiguous frames into power-of-two blocks. It splits a larger block to satisfy a smaller request and joins free buddy blocks on release. On x86_64, the allocator separates MEM32 from memory above 4 GiB so a request can express whether it needs a 32-bit physical address.

The vmemmap region gives the kernel a place to look up metadata by frame number, with backing allocated for physical ranges discovered at boot. Frame references record exclusive or shared ownership. When the last reference to an ordinary allocated frame goes away, its block can return to the buddy allocator.

Mappings

Memory ranges and device registers

vmalloc reserves consecutive virtual addresses and maps backing frames into them. The kernel can use the result as a single buffer even when the physical frames are scattered. A direct-mapped allocation already has a virtual address derived from a fixed offset.

ioremap maps an existing physical range, such as device registers, with a chosen cache type. Releasing that mapping returns the virtual address range. Device memory remains owned by the hardware. PageAllocOptions carries mapping and allocation choices such as cache type, physical contiguity and zero initialization.

Objects

Small allocations and C callers

For small allocations, kmalloc selects a SLUB cache by size. A slab holds multiple object slots, so allocation can reuse a slot without requesting a fresh frame for each object. Larger requests fall back to the page allocator.

kfree uses the metadata of the frame containing the pointer to tell a slab object from a page-backed allocation. The C ABI exposes the allocator to existing drivers. Rust code can also use the Kmalloc allocator with owning types such as Box.

Page tables

Locking and reclaiming page tables

The page-table walker descends from the root to the entry covering a virtual address. PageLock tracks the locked part of that path so mapping and unmapping code can update entries while keeping the backing tables alive.

On unmap, the implementation decrements the table’s entry count. When an empty table can be reclaimed, it clears the parent entry and releases the table frame. This can continue up the tree until it reaches a table that still has mappings or references.

DMA

Memory shared with devices

The DMA layer treats the CPU pointer and the device-visible DMA address as separate values. A device describes constraints such as its address mask and the boundary a transfer must stay within. A coherent allocation can supply a buffer used by both the CPU and the device, such as a descriptor ring.

A streaming transfer starts with an existing buffer. The DMA layer can map it directly when the buffer satisfies the device’s constraints. When it needs a device-accessible copy, it uses a bounce buffer and synchronizes data according to the transfer direction. The C API uses a handle to keep that mapping alive until the driver unmaps it.
