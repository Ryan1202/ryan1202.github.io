Discovery

From firmware tables to a hardware route

ACPI’s MADT tells Horizon which Local APICs and I/O APICs are present. Each I/O APIC covers a range of Global System Interrupts, or GSIs. An ISA source override specifies the GSI, polarity and trigger mode associated with a legacy interrupt line.

The platform records those overrides before setting up interrupt delivery. The I/O APIC routes device interrupts toward a destination Local APIC. The Local APIC delivers the selected vector to its CPU.

Vectors

Translating a vector into a logical IRQ

The hardware line number belongs to an interrupt domain, and Horizon allocates a logical IrqNumber for the kernel to identify the interrupt across domains. The x86 vector is a separate CPU-side delivery number. The vector manager keeps a bitmap and a vector-to-IRQ map for each CPU.

The allocator reserves space for exceptions, legacy ISA vectors, the system-call entry and Local APIC special vectors. Legacy IRQs 0 through 15 retain vectors 0x20 through 0x2f. For a normal device event, the architecture dispatch code uses the receiving APIC and vector to look up the logical IRQ and pass it to the IRQ core.

Handlers

Delivery and shared handler lifetime

request_irq associates a registered handler with a logical interrupt and returns an IrqHandle. A shared IRQ can have several handlers. Dispatch walks the enabled handlers, and each handler can report whether it handled the interrupt. Disabling one shared handler leaves the line enabled while another handler still needs it.

The IRQ flow defines when the controller is acknowledged, masked or sent an end-of-interrupt signal. A level-triggered flow masks and acknowledges the line before calling handlers, then unmasks it if delivery is still enabled. When the last handle goes away, the core masks the line, drains in-flight handling and deactivates its hardware route.

Affinity

Selecting an eligible CPU

The requested affinity mask describes the CPUs eligible for an IRQ. Vector allocation intersects that mask with the online CPU mask and picks an eligible CPU with available vectors. The effective mask records the CPU selected by the hardware route.

When a route changes, the previous vector assignment can still have an interrupt in flight. The routing code keeps the old assignment until it is safe to reclaim, so an already-delivered vector can still be recognized during the change.

Clock events

Periodic events from PIT and Local APIC

The clock-event layer gives the PIT and Local APIC timer a common way to deliver timer events. The PIT supplies the initial periodic ticks. The Local APIC timer measures its counter against those tick boundaries so the kernel can convert a period into a local timer count.

Tick-device selection prefers a timer dedicated to the current CPU over a shared source. The Local APIC timer uses a reserved vector, and its dispatch path acknowledges the Local APIC before calling the timer handler.
